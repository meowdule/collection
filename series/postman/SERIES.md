# Postman 실무 가이드 시리즈

리드·실습용 **따라하기형** 자료집. Vol·Part별 PDF로 배포한다.

---

## 목적

Postman을 처음 쓰는 사람이:

- 복잡한 이론 없이
- 실제로 요청을 보내보고
- 실무 흐름을 빠르게 경험하게 만드는 것

을 목표로 한다.

---

## 핵심 방향

### 교육 교안처럼 만들지 않는다

| 하지 않음 | 대신 |
|-----------|------|
| API 이론 설명 | 따라하기 중심 |
| 기능 백과사전 | 실무 행동 중심 |
| 개발 문서 스타일 | 짧고 빠른 성공 경험 |

---

## 자료집 구조 원칙

### 1. 한 자료집 = 한 행동 흐름

「무엇을 배우는가」가 아니라 **「무엇을 하게 되는가」** 기준으로 쓴다.

**좋은 예**

- 기본 요청 보내기
- Query Params 포함 요청 보내기
- 로그인 요청 보내기
- Token 자동 저장하기

**나쁜 예**

- 상태 코드 이해
- 응답(JSON) 읽기
- HTTP 메서드 설명

→ 이런 내용은 **행동 안에 자연스럽게** 넣는다.

### 2. 짧게 만든다

| 항목 | 기준 |
|------|------|
| 페이지 수 | 본문 3~6페이지(표지·목차·마지막 제외) |
| 읽는 시간 | 3~5분 |
| 문단 길이 | 3줄 이하 |
| 이미지 수 | 최소한 |

### 3. 설명보다 따라하기

```text
1. 입력
2. 클릭
3. 결과 확인
```

### 4. 실무 상황 기준

항상 **「실무에서 언제 쓰는가」** 를 먼저 보여준다.

예: 검색 API 테스트할 때 Query Params를 자주 사용한다.

#### 구현 vs 기획 문서 (1-1~1-3)

- **순서·제목**: 위 표와 레포(`1-1-postman-intro` → `1-2-signup-login` → `1-3-web-install`)가 일치한다.
- **「한 자료집 = 한 행동」**: 1-2·1-3은 부합. 1-1은 “왜 쓰는가” 설명 비중이 크나, Vol.1 첫 파트로 **후속 실습의 동기** 역할이므로 유지해도 무방하다.
- **분량(3~6페이지)**: 아래 표는 **본문 `body` 장 수**(A4 1장 = `pages[]`의 content 1개). 표지·목차·마지막 3장은 공통이라 제외한다.

| Part | 본문 장 수 | 비고 |
|------|------------|------|
| 1-1 | 4 | 기획 상한에 근접 |
| 1-2 | 4 | 적합 |
| 1-3 | 6 | 경로 A/B·Windows 단계 분리로 장 수 다소 많음. 필요 시 웹/앱 중 한 경로만 쓰는 팀용으로 압축 가능 |

## 이미지 가이드

이미지는 **설명용이 아니라 행동 유도용**이다.

**꼭 필요한 화면만**

- Send 버튼
- Params 입력 위치
- Body 탭
- Authorization 위치
- Runner 실행 버튼

**불필요한 캡처 금지**

- 전체 화면 반복
- 장식용 이미지
- 의미 없는 UI 소개

## 문체 가이드

**좋은 예**

- URL을 입력하고 Send를 눌러보세요.
- 401 응답은 로그인 정보가 없는 상태입니다.

**나쁜 예**

- HTTP Request를 Endpoint로 전송합니다.

## PDF 파일명

Part별 PDF 제목·파일명 형식:

```text
vol.1-1 Postman이 뭔가요.pdf
vol.1-2 회원가입 & 로그인.pdf
vol.2-1 기본 요청 보내기.pdf
```

`meta.json`의 `part` 필드(`1-1 Postman이 뭔가요`)에서 자동 생성.  
수동 지정 시 `pdfTitle` 사용.
